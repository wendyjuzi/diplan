# AgentHospital / ClinicalBench Integration (DiPLaN)

This repo now includes a minimal integration path for long-horizon clinical planning tasks inspired by AgentHospital-style workflows.

## 1) Prepare data

Convert raw json/jsonl into DiPLaN unified format:

```powershell
python scripts/prepare_agenthospital_data.py ^
  --agenthospital path\\to\\agenthospital_raw.jsonl ^
  --clinicalbench path\\to\\clinicalbench_raw.jsonl ^
  --out data\\clinical_processed ^
  --seed 42
```

For the cloned `AI_Hospital` repo, use the dedicated adapter:

```powershell
python scripts/prepare_agenthospital_data.py ^
  --ai_hospital_root data\\raw\\AI_Hospital ^
  --ai_hospital_dialog_file dialog_history_gpt4.jsonl ^
  --out data\\clinical_processed_ai_hospital ^
  --seed 42
```

### AI_Hospital precise field mapping

- `task_id`:
  - from `dialog_history_*.jsonl: patient_id` (formatted as `ai_hospital_XXXXXXX`)
- `dataset`:
  - fixed `ai_hospital`
- `question`:
  - composed from:
  - `patients.json: title`
  - `patients.json: medical_record.主诉`
  - `patients.json: medical_record.现病史`
  - `dialog_history: first Patient utterance`
- `oracle_path`:
  - extracted from `dialog_history[*].role/content` using stage-action rules:
  - `Doctor` turns -> `INTAKE/EXAM/DIAGNOSIS/PRESCRIBE/FOLLOWUP`
  - `Reporter` turns -> `EXAM::review_test_results`
  - `Patient` closing turns -> `FOLLOWUP::accept_followup_plan`
  - fallback from `patients.json: medical_record`:
  - `辅助检查`, `诊断结果/初步诊断`, `诊治经过`
- `constraints`:
  - generated by collaboration FSM (`src/diplan/clinical_collab_fsm.py`)

Generated files:

- `data/clinical_processed/clinical_train.jsonl`
- `data/clinical_processed/clinical_val.jsonl`
- `data/clinical_processed/clinical_test.jsonl`

Each sample follows existing DiPLaN fields:

- `task_id`, `dataset`, `question`, `query_tokens`
- `oracle_path`, `trap_path`, `constraints`

## 2) Clinical hard constraints

`evaluate_torch.py` now supports extra constraint fields:

- `required_stage_order`: e.g. `["INTAKE","EXAM","DIAGNOSIS","PRESCRIBE","FOLLOWUP"]`
- `must_precede`: list of `{first, second}`
- `required_before`: map `{target_action: [prereq_action_1, ...]}`
- `forbidden_actions`: list of exact/prefix/stage-level action patterns

These constraints are checked in `_is_feasible(...)` and can be used for both memory prefiltering and execution feasibility scoring.

## 2.1 Multi-agent collaboration state machine (new)

The clinical converter now injects an explicit collaboration FSM into each sample under:

- `constraints.collab_fsm`

Schema:

- `name`: state machine id
- `nodes`: stage nodes with `owner_role` and `action_priors`
- `edges`: legal stage transitions
- `entry_stage` / `terminal_stage`

Related helper module:

- `src/diplan/clinical_collab_fsm.py`

This lets you map AgentHospital workflow semantics (nurse triage -> doctor exam/diagnosis -> treatment -> follow-up) into executable DiPLaN constraints without changing model architecture.

## 3) Evaluate (template config)

Use:

- `configs/eval_torch_clinical_agenthospital.json`

Run:

```powershell
python evaluate_torch.py ^
  --config configs/eval_torch_clinical_agenthospital.json ^
  --ae_ckpt runs\\...\\ae\\best.pt ^
  --planner_ckpt runs\\...\\planner\\best.pt ^
  --value_ckpt runs\\...\\value\\best.pt ^
  --out results\\clinical_agenthospital_eval
```

## Notes

- Raw schema from different repos can vary. The converter accepts common keys:
  - question-like keys: `instruction/question/prompt/task/chief_complaint/case_summary`
  - action path keys: `oracle_path/gold_actions/action_path/plan/trajectory/steps`
- For `steps` list with dict items, action tokenization follows:
  - `STAGE::ACTION` when `stage` is present.

## 4) One-click clinical train/test pipeline

You can run an end-to-end pipeline (AE -> MLP planner -> hard-negative mining -> value model -> test eval):

```powershell
python scripts/run_clinical_agenthospital_pipeline.py ^
  --agenthospital_raw path\\to\\agenthospital_raw.jsonl ^
  --clinicalbench_raw path\\to\\clinicalbench_raw.jsonl ^
  --processed_dir data\\clinical_processed ^
  --seed 42 ^
  --out_root results\\clinical_agenthospital_seed42 ^
  --runs_root runs\\clinical_agenthospital_seed42
```

Main outputs:

- `results/clinical_agenthospital_seed42/pipeline_manifest.json`
- `results/clinical_agenthospital_seed42/test_with_value_eval/summary_metrics.json`
- `results/clinical_agenthospital_seed42/test_with_value_eval/summary_by_dataset.json`

## 5) Closed-loop benchmark (agent-style replanning)

To evaluate DiPLaN as a true agent planner, run the closed-loop benchmark with step-wise replanning and episode traces:

```powershell
python scripts/run_clinical_closed_loop_benchmark.py ^
  --ae_ckpt runs\\...\\ae\\best.pt ^
  --planner_ckpt runs\\...\\mlp_planner\\best.pt ^
  --value_ckpt runs\\...\\value_cross_infonce\\best.pt ^
  --out_root results\\clinical_ai_hospital_closed_loop_seed42
```

This writes:

- `predictions.jsonl` with `episode_trace`
- `summary_metrics.json`
- `summary_by_dataset.json`
- `summary_table.csv`

Use this setting to report agent-style metrics such as `success_rate`, `first_error_step`, `recovery_at_error`, `trap_at_1`, and `replanning_steps`.

## 6) Recommended public benchmarks

For DiPLaN-style planning and replanning, the best-fit public datasets are:

- `ScienceWorld` - long-horizon text-based tasks, good for error recovery and step-wise replanning.
- `WebArena` - realistic browser-agent benchmark, strong for end-to-end agent evaluation.
- `OSWorld` - desktop-level long tasks, the hardest general agent benchmark.
- `ALFWorld` - lightweight embodied text tasks, useful for fast ablations.
- `ToolBench` / `StableToolBench` / `tau-bench` - best if you want tool-use and API-call planning.

Recommended starting combo:

- `ScienceWorld` + `WebArena`

Why:

- `ScienceWorld` tests long-horizon reasoning and recovery.
- `WebArena` tests realistic agent execution and environment feedback.
- Together they cover both "planning depth" and "interaction realism".
